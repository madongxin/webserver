## 进程内微基准（cap 200）

命令：`./build/test/aoi_interest_bench`  
退出码 0。打印 `max_visible=200`。玩家按 3 米间距铺开，格子 32，视野半径 1 格。只移动实例 1 的 1 号玩家，共 200 次。

| 布局 | events | 200 次移动总耗时 |
| --- | --- | --- |
| 1×100 | 19800 | 14.85 ms |
| 1×200 | 39800 | 27.36 ms |
| 1×400 | 23467 | 24129.63 ms |
| 1×1000 | 23186 | 29884.76 ms |
| 4×100 | 19800 | 14.93 ms |

1×100 和 1×200 的邻域没有超过上限，走快路径，所以总耗时是十几到几十毫秒。1×400 和 1×1000 邻域超过 200，每次移动做全量 Top-200，总耗时约 24 秒和 30 秒。4×100 的计时段仍然只移动一张图上的一名玩家，不能当作多核扩展比。

## AOILOAD-01 .. AOILOAD-08

这些编号按提示词的场景定义，不用微基准的行数冒充。

| 用例 | 结果 | 说明 |
| --- | --- | --- |
| AOILOAD-01 200 人进同一 LINE 并静止 | NOT_RUN | 没有走 LINE、没有采 Snapshot/ENTER 字节、CPU、内存 |
| AOILOAD-02 200 人同区域 10 Move/s | NOT_RUN | 微基准只移动 1 名玩家 |
| AOILOAD-03 400 人同一 LINE 均匀分布 | NOT_RUN | 没有 LINE 分布压测 |
| AOILOAD-04 400 人密集、10 Move/s | NOT_RUN | AOI200-09 只证明 400 人同格订阅正确 |
| AOILOAD-05 1000 人单实例研究 | PASS | 上表 1×1000：23186 events，29884.76 ms / 200 次单人移动。不代表一条 LINE 可以放 1000 人 |
| AOILOAD-06 10 实例 × 200 人同时移动 | NOT_RUN | 没有 10 实例并行移动。4 实例用例只验证了 120 次移动的正确性 |
| AOILOAD-07 25×400（1 万 CCU） | NOT_RUN | 本机 4 核 / 3.6G，未跑 |
| AOILOAD-08 1 万登录后再移动 | NOT_RUN | 正式 pid 存在，登录压测被拒绝 |

理论扇出预算（不是实测）：1 万玩家 × 10 次移动/秒 × 200 个观察者 = 2000 万次接收更新/秒。当前进程没有测出这个吞吐。
